# Diangetai · 点歌台

一个部署在 NAS 上的家庭点歌应用：手机扫码点歌，电视 / 平板大屏播放，逐字卡拉 OK 歌词、透明粒子画面、歌曲封面、原唱 / 伴奏切换、拼音搜歌与多端队列管理。

原生 Python 服务，**不依赖 Docker，也不需要已 root 的安卓设备**；仅使用 Python 标准库，无第三方运行依赖。当前版本 **0.0.10**，以 [MIT 协议](LICENSE) 开源。

> **项目主页**：https://haonanren118.github.io/Diangetai/ —— 功能介绍、部署步骤、常见问题与下载入口。
>
> 仓库只包含源码与构建脚本；可直接安装的 `.fpk` 与独立 Docker 部署包请到 [Releases](../../releases) 下载。

## 功能

- **四种点歌方式**：手机扫码、鼠标、电视遥控器（方向键 / OK / 数字键 1~9）、USB 键盘（S 搜歌、Q 队列、N 切歌、P 上一首、T 原唱伴奏、空格播放暂停、左右键快进退）
- **大屏播放**：逐字歌词染色（支持带 `<mm:ss.xx>` 字级时间戳的 LRC）、上一行 / 当前行 / 下一行、封面与虚化背景、透明 canvas 粒子层（有声 / 无声都不黑屏）、可拖动进度条
- **原唱 / 伴奏切换**：曲库里放 `001-歌名-原唱.mp3` + `001-歌名-伴奏.mp3` 时自动使用真实伴奏音轨；没有配对文件时，大屏用 Web Audio 立体声反相抵消（L − R）实时生成消人声伴奏并低通补回低频。切换不重载音频，进度连续，歌词封面同步，切歌自动恢复原唱
- **搜歌**：歌名 / 歌手 / 拼音全拼与首字母（如 `zjl`、`zhoujielun`、`pengyou`），在线曲库与本地曲库都能搜
- **队列管理**：手机与大屏都能看已点队列、跳转播放、删除、清空；队列持久化，重启自动恢复
- **曲库文件夹**：应用内浏览 / 上传歌曲、封面、歌词，一键复制共享目录路径
- **关于与版本管理**：查看代码版本、应用中心版本、作者、端口、共享目录与更新日志；支持上传新版 fpk 一键热更新，失败自动回滚
- **窄屏适配**：手机点歌台与大屏页在 320~390px 视口下不溢出，桌面大屏版式不变

## 快速开始

### 方式一：飞牛 NAS（fnOS）fpk

1. 从 [Releases](../../releases) 下载 `diangetai-0.0.10.fpk`。
2. 在飞牛「应用中心」手动安装该 fpk（也可由 `appcenter-cli install-local` 走正规安装链路）。
3. 安装完成后应用自动启动，端口 `18090`。

### 方式二：独立 Docker 部署包

下载 `diangetai-docker-0.0.10.zip`，解压后在目录内执行：

```
docker compose up -d --build
```

此方式适用于任意 Docker 主机，但**不支持应用内热更新**，升级请替换部署包后重新执行上面的命令。

### 访问地址

| 用途 | 地址 |
| --- | --- |
| 点歌台（手机） | `http://<NAS_IP>:18090/` |
| 大屏播放（电视 / 平板） | `http://<NAS_IP>:18090/tv` |
| 曲库文件夹 | `http://<NAS_IP>:18090/files` |
| 关于 / 版本管理 | `http://<NAS_IP>:18090/about` |

把 `<NAS_IP>` 换成 NAS 在局域网中的地址。首次打开大屏需点击一次「开启大屏」，浏览器才允许自动播放；手机与电视需在同一局域网。若大屏以 localhost 打开导致二维码不可用，在「点歌」面板底部把地址改成本机局域网地址后点「应用并换码」。

## 本地曲库

把歌曲放进共享目录的 `music/`，命名建议 `001-歌名-歌手.mp4`（或 `.mp3`）：

- 同名 `.lrc` 作为歌词；同名 `.jpg` / `.png` 或目录下的 `cover.jpg` 作为封面
- 支持 `mp3 / mp4 / m4a / flac / wav / aac / ogg / mkv / avi / mov`
- 已点队列保存在 `data/state.json`
- 在线歌曲自动取专辑封面；在线曲库使用网易云公开接口，只保留实测可播放的曲目

用户可见的共享文件夹名为 `diangetai`，界面显示为「点歌台 / music」。

## 版本与热更新

关于页会同时显示**代码版本**（来自 `app-src/version.json`）与**应用中心版本**（来自应用 manifest）。二者不一致时说明安装未完成，可直接看到。

飞牛 fpk 版的「在线升级」流程：

1. 上传新版本 fpk（或从配置的更新源检查更新）；
2. 自动备份当前版本、走 `appcenter-cli install-local` 完成停止 → 安装 → 启动；
3. 应用中心版本号随新包 manifest 一起更新，代码版本与应用中心版本保持同步；
4. 已点队列、歌曲、封面保留；安装失败自动回滚到备份版本。

**版本纪律**：每个发布内容使用全新版本标识，已发布的旧版本包与 Release 不会被覆盖或替换。

### 检查更新该填什么 / 有新版本怎么提示

「关于」页的「检查更新」需要一个返回 JSON 的 **version.json 直链**，格式如下：

```json
{
  "version": "0.0.10",
  "changelog": "更新日志",
  "url": "https://github.com/haonanren118/Diangetai/releases/download/v0.0.10/diangetai-0.0.10.fpk"
}
```

官方更新源（由项目主页托管，每次发版同步）：

```
https://haonanren118.github.io/Diangetai/version.json
```

- **一键填入**：0.0.9 起关于页有「使用官方更新源」，点一下自动填入并检查；不配置更新源也能收到提示。
- **主动提示**：手机点歌台首页与关于页在打开时会自动检查一次，发现新版本会显示金色提示条 / 醒目文案，点击可直达升级；结果缓存 6 小时，失败 5 分钟后重试，不阻塞页面、不影响大屏播放（大屏保持纯净无提示）。
- **填错不再甩异常**：填了仓库主页、Releases 网页等 HTML 地址，或返回空内容 / 非法 JSON，会明确提示「返回的不是 JSON」并附上响应摘要，不再显示 `Expecting value: line 7 column 1` 这类 Python 原始报错。
- **留空即清除**：把输入框清空后点「检查更新」会清掉已保存的更新源，改为直接用下方上传 fpk 的方式升级。

## 排障：歌源 / 热歌榜一直在加载

**现象**：装好后打开点歌台，热歌榜转圈几十秒甚至一直显示「加载中」，本地曲库却正常，网速也不慢。

**根因**：有些 NAS / 主机拿到了 IPv6 地址和默认路由，但 IPv6 出口实际不通。系统默认把 AAAA 记录排在 A 记录前面，建连时先尝试 IPv6，一直等到请求超时（12 秒）才回退 IPv4；一个榜单要问 4 个歌单，排队就是 40 秒起步。

**0.0.8 起已在代码层修复**：外网连接默认只解析 IPv4（A 记录），不再依赖机器的 `/etc/gai.conf`；更新源检查与更新包下载同样生效。升级到 0.0.8 及以上版本后重启一次应用即可，无需改系统配置。

自行确认是不是同一问题（把 `<NAS_IP>` 换成 NAS 的局域网地址）：

```bash
# 应用接口耗时；冷启动会有一次探测，之后应明显变快
curl -s -o /dev/null -w '%{time_total}\n' http://<NAS_IP>:18090/api/hot

# 对比 IPv6 与 IPv4 出口
curl -6 -m 6 -s -o /dev/null -w 'ipv6 %{http_code} %{time_total}\n' https://music.163.com/
curl -4 -m 6 -s -o /dev/null -w 'ipv4 %{http_code} %{time_total}\n' https://music.163.com/
```

若 `curl -6` 超时而 `curl -4` 正常，就是这个原因。可选的系统级修复（对所有程序生效，需要 root）：

```conf
# /etc/gai.conf
# 必须是 100：模板里注释掉的 10 低于 IPv6 默认的 40，去了注释也不生效
precedence ::ffff:0:0/96  100
```

一旦写了自定义 `precedence`，系统默认表就不再生效，稳妥起见把默认表补齐：

```conf
precedence  ::1/128       50
precedence  ::/0          40
precedence  2002::/16     30
precedence  ::/96         20
precedence  ::ffff:0:0/96 100
```

改完重启应用或容器，清掉进程内的 DNS / 连接缓存。纯 IPv6 网络可设环境变量 `KTV_IPV4_ONLY=0` 关闭应用内的 IPv4 优先策略。

## 从源码构建

无需安装任何第三方依赖，Python 3.11 及以上标准库即可：

```
python build.py
```

`build.py` 会集中生成：

- 原生 fpk 工程目录（应用名、显示名、版本、作者、端口、共享目录、生命周期脚本、图标与 manifest）
- 独立 Docker 部署目录与 zip 包（含 `docker-compose.yaml`、`Dockerfile`、`README.md`）
- `app-src/version.json`（版本号与更新日志）

将工程目录用飞牛官方 `fnpack build -d <工程目录>` 打包即可得到 `.fpk`。构建脚本顶部的常量集中管理 `APPNAME` / `DISPLAY` / `VERSION` / `AUTHOR` / `PORT` / `SHARE_NAME`，改版本号只需改 `VERSION`。

```
        ├── tv.html           # 电视大屏
        ├── files.html        # 曲库文件夹
        └── about.html        # 关于 / 版本管理 / 在线升级
```
